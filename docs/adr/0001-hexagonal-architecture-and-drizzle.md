# ADR 0001 — Hexagonal architecture + Drizzle ORM

Status: accepted (2026-07-29)

## Context

The scanner is a learning project intended to become a commercial scan-as-a-service
product. Two swaps are already on the roadmap: the scan **worker will be rewritten
in Rust**, and an **event bus** (Kafka/NATS/…) may be added later. The domain is
thin today (Target, Scan, Finding) but the external boundaries are real: Postgres,
a job queue, external CLI tools (nmap/nuclei), and HTTP. The owner values reading
and understanding the whole codebase.

## Decision

**Hexagonal (ports & adapters), applied lean.**

- `domain/` holds entities, port interfaces, and the `ScanService` use-cases. It
  imports nothing from `adapters/`.
- `adapters/` holds one implementation per port: Drizzle repositories, a pg-boss
  queue, the nmap+nuclei scanner, a Fastify HTTP delivery, and a queue worker.
- `main.ts` is the composition root — the only place adapters meet the domain.
- Classes with constructor injection (owner preference).
- Lean: **no** DTO/mapper layer and **no** one-class-per-use-case (Clean
  Architecture ceremony) until the domain is rich enough to earn them.

**ORM: Drizzle**, confined to `adapters/persistence/`.

## Why

- The planned Rust worker and event bus are literally "new adapters behind
  existing ports" — the swap seams are known, not speculative, so ports & adapters
  is building the seam where the change is already coming, not premature generality.
- Faking the `VulnerabilityScanner` port already keeps the fast test suite at ~2s
  instead of ~5min; the same pattern makes the DB and queue fakeable too.
- Drizzle is SQL-close, schema-is-TypeScript, no codegen or query-engine binary —
  best fit for "understand exactly what runs." Prisma's ergonomics/ecosystem win
  the axes that matter least here, given hexagonal already isolates persistence.

## Consequences

- More files (~11 vs 6), each small and single-purpose.
- The dependency rule (`domain/` imports no adapter) must be held by discipline.
- Migrations are plain `.sql` generated by `drizzle-kit` and applied on startup.
- If the domain grows rich (scan policies, findings lifecycle, scheduling), revisit
  toward Clean Architecture's use-case/mapper layers — this is the on-ramp, not a
  dead end.
